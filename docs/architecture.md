# Архитектура и API

## Стек и границы

Сохранены React, TypeScript и Vite. Сервер использует стандартные `node:http`, `node:sqlite`, `node:crypto`, запуск TypeScript встроенными средствами Node 24.16+. Новые зависимости: Zod — единая исполняемая схема DTO/хранилища и серверная валидация; `@fontsource-variable/inter` — локальные кириллические шрифты. Тестовые зависимости: типы Node и axe для автоматического сканирования. Удалены неиспользуемые HTML-парсер/Tailwind/PostCSS: прежняя привязка обработчиков к текстам и CSS-классам заменена предметными React-компонентами, стиль воспроизведён обычным CSS. После удаления ненужных цепочек локальный `npm audit` не показывает известных уязвимостей на момент проверки. Это не гарантия отсутствия будущих уязвимостей.

- `shared/model.ts`: типы, схемы сущностей/ссылок, даты, деньги, составы, балансы и метрики.
- `shared/permissions.ts`: общая матрица разрешений; обязательно вызывается сервером.
- `server/domain.ts`: валидация команд, переходы, конфликты, финансовые инварианты.
- `server/store.ts`: SQLite, сессии, пароли, транзакции, идемпотентность и проекции доступа.
- `server/http.ts`: API, Origin/CSRF, ограничения запросов, безопасные ошибки, static/SPA fallback.
- `server/integrations.ts`: контракты тестового и ненастроенного провайдеров.
- `server/csv.ts`: CSV, защита выгрузок от формул, импорт с валидацией.
- `src/api.ts`, `actions.tsx`, `screens.tsx`, `components.tsx`, `main.tsx`: клиентский транспорт, формы, предметные экраны, доступные диалоги и оболочка.

SQLite хранит агрегат каждой школы JSON-записью со schemaVersion и revision, отдельные таблицы пользователей, сессий и обработанных запросов. Ссылки/уникальность проверяются схемой и предметными командами в `BEGIN IMMEDIATE`. Такой подход минимален и позволяет атомарный сценарий без дополнительного сервиса; цена — блокировка записи на уровне базы, полная сериализация агрегата и отсутствие пригодности для большого объёма без дальнейшей нормализации SQL. Старые локальные демонстрационные записи намеренно не становятся рабочими автоматически.

## HTTP-контракт

Все ответы API — JSON, кроме CSV. Для авторизованных изменений нужны cookie сессии и `X-CSRF-Token` из `/api/session`; cookie — HttpOnly, SameSite=Strict, Secure при соответствующей настройке. Срок сессии — 8 часов. В localStorage не сохраняются ни токены, ни персональные/финансовые данные. Сервер проверяет Origin и не открывает CORS. Вход ограничен по частоте на IP; это локальная защита, не распределённый антибрутфорс.

| Метод / URL | Содержание |
|---|---|
| GET /api/health | Доступность, версия схемы, demo; без персональных данных |
| POST /api/login | `{email,password}`; cookie и Session |
| GET /api/session | Пользователь, роль, филиалы, CSRF, истечение |
| POST /api/logout | Отзыв сессии, очистка cookie |
| GET /api/state | Снимок разрешённой школы/филиалов, ограниченный для преподавателя |
| GET /api/records?entity=students&page=1&limit=25&q=... | Серверный поиск/пагинация справочников, до 100 строк |
| POST /api/commands | `{requestId,revision,command}`; `{entityId,revision,replayed}` |
| POST /api/import/preview | `{csv,branchId}`; проверка до 100 строк на копии без записи |
| GET /api/export/students.csv | Разрешённые ученики, безопасный CSV |
| GET /api/export/finance.csv | Оплаты/возвраты, суммы в копейках |

Типизированный union Command определяет доступные операции. Никакого универсального API редактирования финансовых таблиц или аудита нет. На повтор requestId с тем же пользователем и командой возвращается сохранённый результат до проверки версии. Изменённое тело под тем же ключом даёт 409. Конфликт revision даёт 409 и не меняет состояние. Клиент обновляет снимок после конфликта, сохраняет поля формы и требует осознанно повторить действие. Формы справочников, занятий и явки передают исходные значения: при повторе разные поля объединяются, конфликт одного и того же поля отклоняется с актуальным значением; незаметно затереть правку коллеги нельзя. Сетевой сбой сохраняет тот же ключ для безопасного повтора.

Ошибки имеют `error`, `field`, `requestId`. Коды: 400 — JSON, 401 — сессия, 403 — права/CSRF, 404 — недоступный объект/маршрут, 409 — предметный/конкурентный конфликт, 413 — размер, 415 — content-type, 422 — поля, 429 — вход, 500 — внутренняя ошибка, 503 — хранилище/ненастроенный провайдер. Клиент не показывает ложный успех до подтверждения команды и обновления снимка. Логи 5xx содержат только correlation ID, status, code; тела/контакты/пароли не логируются.

## Роли

| Действие | Директор | Администратор | Преподаватель | Финансист |
|---|---|---|---|---|
| Справочники учеников/групп/кабинетов/педагогов | да | да | нет | нет |
| Филиалы, настройки школы, закрытие периода | да | нет | нет | нет |
| Создание/изменение/отмена открытых занятий | да | да | нет | нет |
| Явка | да | да | только свои занятия | нет |
| Явка закрытого периода | с основанием | нет | нет | нет |
| Тарифы | да | нет | нет | да |
| Выдача, оплата, заморозка, продление, кредит остатка | да | да | нет | да |
| Возврат денег | да | нет | нет | да |
| Импорт учеников | да | да | нет | нет |
| CSV-выгрузки | да | да | нет | да |
| Черновики / тест провайдера | да | да | нет | да |

Преподаватель получает только собственные занятия и связанные с ними группы/учеников; контакты учеников/коллег и финансовые коллекции скрыты серверной проекцией, аудит и представители не выдаются. Идентификаторы проверяются внутри школы и разрешённых филиалов. Попытка подменить ID в прямом запросе не обходит проверку. Существующие авторизованные роли нельзя изменить через команды фронтенда.

Официальные контракты используемого runtime: [Node.js SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html), [Node.js TypeScript](https://nodejs.org/docs/latest-v24.x/api/typescript.html). Наличие API дополнительно проверено запуском в указанной локальной версии Node.
