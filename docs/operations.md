# Эксплуатация, восстановление и непроверенные внешние свойства

## Запуск

Node 24.16+, локальный диск с правами на каталог `data/`. Минимум один процесс API; сервер слушает 127.0.0.1 по умолчанию. `npm run build` создаёт `dist/`. `npm start` раздаёт сборку и API; известные вложенные URL работают через SPA fallback. Файлы assets получают immutable cache, index — no-cache, API — no-store. Локальные проверки заголовков не подтверждают настройки внешнего reverse proxy.

Рабочая база не содержит seed. Первый директор создаётся только при пустой базе с ADMIN_EMAIL/ADMIN_PASSWORD. Демосреда требует `--demo` и использует другой файл; попытка открыть демобазу рабочим сервером или наоборот отклоняется. Не копируйте демобазу в рабочий режим. Пользователи/пароли хранятся отдельно от состояния школы, пароль — salted scrypt, сессия в базе — hash токена.

Новая схема — версия 1. Синтаксис, структура, ID и ссылки проверяются при чтении и записи. Неизвестная версия user_version > 1 отвергается без понижения; повреждённые записи не заменяются пустыми данными. Аддитивное поле notificationReads имеет явное значение по умолчанию для ранних серверных снимков версии 1. Полноценной миграции прежнего localStorage нет: для переноса используется проверяемый CSV с предварительным просмотром. Если запуск сообщает повреждение/несовместимость, остановите сервер и восстановите проверенную копию в новый файл.

## Резервирование и восстановление

Пример PowerShell (путь назначения должен быть **новым**):

```powershell
$env:DB_PATH = 'data/work.sqlite'
npm run db:backup -- backups/work-2026-10-18.sqlite
$env:DB_PATH = 'backups/work-2026-10-18.sqlite'
npm run db:restore -- data/restored.sqlite
```

Используется SQLite backup API, а не копирование открытого `.sqlite` без WAL. Каждая копия проверяется integrity_check и StateSchema. Существующее назначение не перезаписывается. Восстановление выполняется в новый файл; после проверки переключите DB_PATH и запустите сервер в правильном режиме. В тестах выполнен цикл backup → restore → сравнение состояния; это проверка механизма на синтетических данных, не проверка удалённого хранилища.

Предлагаемый эксплуатационный регламент: копия каждые 24 часа и перед обновлением; зашифрованная копия вне сервера; ежедневные 7, недельные 4; проверка восстановления ежемесячно. Предложенные цели RPO ≤24 ч, RTO ≤1 ч **не подтверждены** на инфраструктуре пользователя. Планировщик, удалённое шифрованное хранилище, контроль выполнения и согласование целей остаются внешними задачами. В тестах резервные каталоги создаются через mkdtemp и не содержат пользовательских данных.

## HTTPS и защита среды

Для внешнего запуска нужны действующий HTTPS reverse proxy, APP_ORIGIN равный адресу приложения, COOKIE_SECURE=1. API устанавливает CSP (self, запрет frame-ancestors, inline-скриптов), nosniff, Referrer-Policy, X-Frame-Options, при secure — HSTS. Cookie/Origin/CSRF проверены локально; TLS-цепочка, редиректы, реальные заголовки после proxy и HSTS на домене не проверены. Не выставляйте порт dev-сервера в интернет.

Каталог базы содержит персональные и финансовые данные: права только оператору процесса, шифрование диска/резервных копий и политика хранения нужны на хосте. Автоматического удаления финансовой истории нет: архив ученика сохраняет связанные записи. Владелец школы должен утвердить сроки и основания хранения и удаления данных. Репозиторий и тесты содержат только вымышленные данные.

## Обновление и откат

Перед обновлением остановите изменение данных, создайте backup, сохраните SHA предыдущей версии и lockfile. Соберите новую версию, выполните тесты, переключите процесс. Для отката используйте прежний commit и **совместимую** копию базы в новом файле; не открывайте неизвестную схему старым кодом. Внешняя автоматическая выкладка/откат не выполнялись. Стартовые ошибки и 5xx имеют безопасные диагностические сообщения; централизованный сбор/оповещение оператора ещё не подключены.

## Интеграции и браузеры

TestAdapter поддерживает контракт для email/SMS/онлайн-платежа/учётной системы и возвращает `realDelivery:false`. В демоинтерфейсе это подписано как тест. UnconfiguredAdapter рабочего режима отвечает 503, не отмечает счёт отправленным и не создаёт подтверждение онлайн-оплаты. Нет webhook, проверки подписи реального провайдера, кассового чека или доставки SMS/email. Нужны выбор поставщиков и реквизиты.

Проверен Chromium из lockfile Playwright на Windows. Другие движки и реальные мобильные устройства, экранная клавиатура и NVDA не проверены. Автоматический axe и reflow не заменяют ручную проверку WCAG 2.2 AA.
