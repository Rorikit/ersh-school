# ЁРШ CRM

Серверный учёт частной школы: React 19, TypeScript, Vite, Node.js **24.16+**, SQLite. Интерфейс сохраняет светлую палитру и композицию исходного проекта. Главная и восемь предметных разделов подключены к одному серверному источнику. Это локально проверенная реализация; готовность внешнего хостинга и реальных интеграций не подтверждена.

## Быстрый запуск демонстрации

```sh
npm ci
npm run dev
```

Откройте http://localhost:5173. Команда запускает Vite и API на 3001. Данные демосреды сохраняются в `data/demo.sqlite`. База игнорируется Git, не отправляется в репозиторий. Старый localStorage проекта не читается, не очищается и автоматически не импортируется.

Только в явно включённой демосреде доступны аккаунты:

| Логин | Роль |
|---|---|
| director@demo.local | Директор |
| admin@demo.local | Администратор |
| teacher@demo.local | Преподаватель (teacher-0) |
| finance@demo.local | Финансист |
| other@demo.local | Директор другой тестовой школы |

Демонстрационный пароль: `Demo-School-2026!`. Вход, интерфейс и API явно обозначают демосреду. Никаких реальных сообщений, онлайн-платежей или чеков эти аккаунты не отправляют.

Для просмотра собранного приложения: `npm run build`, затем `npm run start:demo`; адрес http://localhost:3001. Для входа через этот адрес задайте `APP_ORIGIN=http://localhost:3001` (иначе API ожидает origin dev-сервера 5173).

## Рабочий режим и аккаунты

`npm start` запускает API и раздаёт `dist/` с SPA fallback. Рабочая база по умолчанию — `data/work.sqlite`, демонстрационные пользователи и данные в неё не добавляются. Первый запуск требует `ADMIN_EMAIL` и уникального `ADMIN_PASSWORD` не короче 14 символов. Используйте `.env.example` как перечень переменных, **замените** пример пароля. `.env` не загружается автоматически: можно выполнить `node --env-file=.env server/index.ts`. Для локальной HTTP-проверки задайте `APP_ORIGIN=http://localhost:3001`, `COOKIE_SECURE=0`; для внешнего HTTPS — реальный origin и `COOKIE_SECURE=1`.

Создание дополнительных пользователей выполняется администратором сервера:

```powershell
$env:DB_PATH = 'data/work.sqlite'
$env:USER_EMAIL = 'admin@example.org'
$env:USER_PASSWORD = '<уникальный пароль от 14 символов>'
$env:USER_ROLE = 'admin'
$env:USER_NAME = 'Администратор'
npm run db:user
```

Дополнительные переменные: `SCHOOL_ID`, `BRANCH_IDS` (ID через запятую), `TEACHER_ID` (обязателен для преподавателя). Для демобазы передайте `-- --demo`. Секреты не сохраняются в Git и не выводятся в лог. Интерфейс управления пользователями и самостоятельное восстановление забытого пароля не входят в эту реализацию; аккаунт выдаёт оператор сервера.

## Проверки

```sh
npm run build
npm run typecheck
npm test
npx playwright install chromium
npm run test:e2e
npm audit
```

E2E сами запускают HTTP-сервер и **отдельную SQLite `:memory:` для каждого теста**. Не нужен заранее открытый localhost; не очищаются браузерные данные чужого приложения. Часы и синтетические данные фиксированы только в тестовых fixtures. Основной сервер использует действительную дату школы. Скриншоты ошибок и трассы — `test-results/`, HTML-отчёт — `playwright-report/`. Эталон визуальной регрессии — `tests/workflows.spec.ts-snapshots/`; обновляйте только после просмотра: `npm run test:e2e -- --update-snapshots`. Обновление эталона само по себе не является доказательством прохождения регрессии.

CI `.github/workflows/ci.yml`: установка по lockfile, типы, сборка, предметные/API/backup-тесты, E2E, аудит зависимостей и отчёты. Внешнее выполнение CI проверяется отдельно от локального прогона.

## Ограничения

Нет подтверждённых HTTPS-развёртывания, внешних резервных копий, SMS/email, эквайринга, кассы и бухгалтерии. Вместо внешних интеграций есть проверяемые адаптеры: явный тестовый результат в демосреде и отказ 503 без реквизитов в рабочей. Нет заявления о ручной проверке NVDA, Safari/Firefox или промышленной нагрузке. Сервер хранит агрегат школы в одной транзакционной записи; при росте базы потребуется нормализация SQL, потоковая выдача и отказ клиента от полного снимка. CSV реализован; XLSX не реализован. P3 перечислены в матрице отдельно.
